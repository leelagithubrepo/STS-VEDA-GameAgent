# Automation readiness report

`scripts/check_automation_readiness.py CHECKPOINT --output NEW_REPORT` inventories implementation support for a historical strategy checkpoint. It reads at most 1 MB, binds the report to the exact input bytes, and leaves existing output files untouched. Exit 0 means the report was produced; it does not mean automation is ready. Exit 2 means the input or output could not be processed.

The report preserves exact card variants and duplicate counts. A checked numeric effect, a routine-planner candidate, a reviewed selection flow, and an action ready to execute now are separate capabilities. For example, base True Grit has a checked Block effect and a random-exhaust boundary. The exhausted card remains unknown until observed. The generic reviewed selection flow does not add True Grit+'s missing exact card effect or routine candidate. Headbutt's routine candidate still requires a confirmed empty discard pile; a nonempty return selection can use a separate complete reviewed choice contract.

`implementation_inventory` now records the implemented choice planner, play telemetry connector, Codex-reviewed session and Collector A2 survival bound. The [choice planner](veda-choice-execution.md) supports supplied selection, potion, map, reward, rest, event, shop and same-run Continue contracts. The [telemetry connector](veda-play-telemetry.md) records pending decisions and observed inventory, zone and lifecycle outcomes, with crash recovery and an explicit resume boundary. Their presence does not establish correct current screen interpretation, strategy, button mappings or end-to-end hardware behavior.

`execution_paths` distinguishes two paths. The standalone automatic runtime still lacks a validated complete reader and its reader-bound calibration evidence. The Codex-reviewed session instead requires an active reviewer to inspect each fresh source, supply complete relevant facts, check the decision and verify the result of one input. This separate path does not claim automatic recognition or satisfy the standalone runtime's calibration gate.

Relic allowlisting does not claim a complete interaction simulator. Recorded potion slots do not establish current contents; the reviewed potion path needs the actual slot, menu, target and outcome evidence. Fairy in a Bottle remains automatic and is not manually drinkable. Collector's A2 support now bounds damage conservatively for the observed Fireball, Buff, Mega Debuff, Spawn/Revive and Torch Head Tackle moves. It requires the complete current roster, displayed hits, modifiers, typed move evidence and supported relic/effect context. It does not predict exact future statuses, roster, action order, other Ascensions or the next rolled move. The report registers that capability without calculating a bound from the historical checkpoint.

The remaining gates concern complete automatic recognition and independent validation for the standalone path, and current reviewed contracts and end-to-end validation for the Codex-reviewed path. Fresh game evidence, bridge preflight and per-run arming remain necessary. A code capability marked `implemented` is not a passed live gate. The report always returns `runtime_authorized: false`, `controller_authorized: false` and `autonomy_ready: false`; no executable action is established from the checkpoint. Caller-provided flags and calibration summaries cannot change those results. A recent checkpoint timestamp is still historical metadata, not a fresh game observation.

This command does not capture a screen, follow linked evidence paths, connect to SQLite, invoke a model, contact the bridge or send input. It is an implementation inventory, not a tactical recommendation or an authorization mechanism.
